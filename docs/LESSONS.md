# Lessons

- **Symptom:** Mermaid fences show as raw “Code block” with no 源码/图表 buttons on DSH ≥0.2 desktop/web. **Cause:** Chat always passes `toolbarLabels`; `CodeToolbar` prints the localized fallback when `supportsHighlighting(lang)` is false (mermaid has no Shiki grammar), so the old `.infostring === "mermaid"` / `code.language-mermaid` detectors never fire, and the action cluster is `[data-code-block-banner] …actions` not `.banner .action`. **Fix:** Detect via language label, legacy hooks, or first-line Mermaid diagram keywords; inject into `[data-code-block-banner] [class*="actions"]`.
- **Symptom:** After “Load earlier”, scrolling toward a large off-screen Mermaid fence freezes the chat UI for seconds (CPU fan spins). **Cause:** DSH mounts the whole loaded history window (no transcript virtualization); the plugin’s DOM scan eagerly called `mermaid.render()` for every fence on insert, so a heavy layout ran on the main thread while the user was still scrolling. **Fix:** Gate first render with `IntersectionObserver` (+ settle debounce; cancel if the fence leaves the preload margin), and cache SVG by source+theme. Mirrors DSH’s own viewport-gated Shiki path in `useViewportHighlighting`.
- **Symptom:** Even with viewport gating, chat + side pane still freeze while a large diagram shows “渲染中…”. **Cause:** `mermaid.render()` is CPU-heavy layout on the page’s JS thread; deferring *when* it starts does not stop it from monopolizing that thread (scroll/input die until it finishes). **Fix:** Run Mermaid inside a hidden `sandbox="allow-scripts"` (no `allow-same-origin`) `srcdoc` iframe and return SVG via `postMessage`. Desktop Chromium ≥127 puts those frames in a separate renderer process, so the parent UI stays responsive; preview mounts the result as a blob `<img>` to avoid a huge inline-SVG layout tax. Fall back to in-page `mermaid.render` only if the worker fails to boot.
